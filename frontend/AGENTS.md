# frontend/AGENTS.md

The React app for customers and the back office. It has its own toolchain (npm, Vite, FSD,
Tailwind), hence its own file; the root `AGENTS.md` covers the process and the contract.

## Map

```
src/app        router, routes, styles
src/pages      application-list, application-detail, submit-application, task-inbox, not-found
src/widgets    app-shell, application table/summary/actions, leasing-progress, task-inbox-list
src/features   one write each: submit, sign, handover, withdraw, credit check, reversal
src/entities   reads: leasing-application, bike, user-task
src/shared     generated API client (orval), ui kit, i18n (de/en)
e2e/           Playwright scenarios against the running stack
```

## Stack

React 19 · TanStack Router (file routes) + Query · Tailwind v4 (`@theme`, CSS-first) · radix-ui +
cva shadcn-style primitives · react-hook-form + zod · orval-generated client · Vitest + MSW ·
Playwright. npm only, Node in the version from `.nvmrc`, every version pinned exact (`.npmrc`
`save-exact=true`).

## Feature-Sliced Design (enforced)

Layers, strictly downward: `app → pages → widgets → features → entities → shared`. Every slice has a
public `index.ts`; import other slices only through it. Segments: `ui model api lib config`.

- **`src/processes/` is banned**: "process" means the BPMN model here. The step rail is
  `widgets/leasing-progress`.
- **Entities own reads, features own writes** (one mutation, its cache invalidation and a toast
  each). Widgets compose features, pages compose widgets, and routes (`app/routes/`) hand plain props
  to router-free pages.
- **Only `entities/*/api` and `features/*/api` may import `@/shared/api/generated`.**

Enforced by `steiger` (`npm run lint:fsd`, `--fail-on-warnings`, disabled rules reasoned in
`steiger.config.ts`), ESLint `no-restricted-imports` and `knip` (`npm run lint:deadcode`).

## The generated client

`src/shared/api/generated/` is generated by orval from `../openapi/openapi.json` and committed.
Never edit it by hand. After the backend contract changes, run `npm run api:generate`, fix
TypeScript, and make sure `npm run api:check` is clean. Requests go through the hand-written
`shared/api/http-client.ts` mutator.

## Design system

Tokens live in one `@theme` block in `src/app/styles/theme.css` (Miragon CI). Use the named type
utilities (`text-h1` … `text-klein`) and the palette (`blau`, `gruen`, semantic `success` /
`warning` / `danger` / `info`), no arbitrary values. **Green is accent-only** (fails AA as text);
`shared/ui/ci-guard.test.ts` fails if `text-gruen` appears in a `.tsx`. Icons: Lucide,
`strokeWidth={1.75}`.

## State, forms, copy

- **Polling is the point.** Every action except the submit (200) returns 202 and the engine advances asynchronously, so the
  detail page polls every 2 s until `isTerminal` (`ACTIVE | REJECTED | CANCELLED`) or an error, and the
  list and the inbox poll every 2 s. Don't "fix" this away.
- **A 409 means the case moved on.** The action features check `isConflict` (`shared/api`), show
  `common.conflictToast` and re-read the detail, the list and the inbox, never the raw problem
  `detail`.
- **Query keys** come from orval; `entities/leasing-application/api/keys.ts` adds the `all`
  invalidation prefix (unit-tested).
- **Forms must not duplicate process rules.** The submit form reuses the generated
  `SubmitLeasingRequestBody` and only checks shape. It must not check `age >= 18` or the bike
  catalogue: that is the process's _Validate application_ step.
- **Back-office decisions** (credit check, reversal) live in the `/aufgaben` inbox, not on the detail
  page, which only offers the customer actions the process waits for (`available-actions.ts`).
- **Copy** lives in `shared/i18n` (`de.ts` is the master, `en.ts` must match its shape); components
  never hard-code text. The tone is tested (`de.tone.test.ts`, `i18n.parity.test.ts`): lowercase
  starts, no "Sie", proper umlauts, no em-dashes.
- **No auth.** A fork that adds it injects the header in `shared/api/http-client.ts` and guards
  routes in `app/routes/`.

## Commands

`npm run verify` runs `format:check → lint → lint:fsd → lint:deadcode → typecheck → test`. Others:
`dev build typecheck test api:generate api:check e2e`. The dev server runs on 5173 and proxies
`/api`, `/v3/api-docs`, `/engine-rest`, `/camunda` and `/webapp` to the backend on 8081 (`nginx.conf` does the
same in the container). Playwright specs in `e2e/` drive the real app against a running backend.

## End-to-end tests

The engine advances asynchronously, so a spec never sleeps (`waitForTimeout`, `setTimeout`). It waits
for the visible outcome with web-first assertions (`await expect(locator).toHaveText(…)`), which retry
until the timeout. Locate by role, label or accessible name, the way a user finds things. Build state through
the UI with the helpers in `e2e/helpers/ui.ts` (reuse them before writing new ones) and name cases with
`uniqueName`, because the list and the inbox are shared between tests. Run one spec with
`npm run e2e -- e2e/<name>.spec.ts`.
